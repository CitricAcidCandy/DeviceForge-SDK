# 独立仓库迁移与验证

## 本次范围

从DeviceForge迁出Rust插件SDK、协议运行库、依赖清单公共库、浏览器SDK、公开HTTP类型、浏览器构建工具和两端开发指南。宿主保留业务、运行管理、CLI和发布安装实现，改为消费这些公开包。

本地推荐目录为同级的DeviceForge与DeviceForge-SDK。Rust通过明确的外部Cargo路径消费公共库；浏览器通过file依赖和公开包出口消费。旧浏览器内部路径只保留转发，不再保存契约实现。MCP在编译时嵌入同级SDK仓库的指南，已打包的运行程序不要求运行时读取SDK目录。

## 验证边界

验证按迁移范围执行：

- 源文件与迁移前提交逐字节比对，除独立工作区和包元数据调整。
- Rust公共库及协议4示例独立解析、编译和定向测试。
- 浏览器SDK/构建工具独立构建、打包和声明消费。
- 宿主相关Cargo依赖、SDK入口、公开指南与打包接线检查。
- 新仓库不依赖宿主node_modules或公共库源码路径。

不为本次迁移运行设备、界面、全量业务回归或重启用户服务。各项实际结果在迁移完成后更新；未执行的检查不计为通过。

## 发行

浏览器包先按根package.json的pack:browser生成，完整SDK源码发行从本仓库提交导出，包含Rust公共库、独立锁文件、指南和可运行示例，不附带宿主源码。配套CLI使用宿主已验证的平台发行包。scripts/prepare-release.ts只整理实际文件、大小、SHA-256、源码修订与兼容性清单，不自动发布或推测下载地址。

在源码提交后执行以下命令生成本地发行材料：

```powershell
npm run prepare:release -- --cli <已取得的deviceforge-cli-0.1.0.tgz绝对路径>
```

结果位于`release-output/`，包含三份浏览器TGZ、完整SDK源码ZIP、可选配套CLI，以及`manifest.json`和`SHA256SUMS.txt`。开发材料不是可导入插件市场的业务插件；实际公开附件状态以GitHub发行页为准，不把本地prepared清单描述成已经发布。
